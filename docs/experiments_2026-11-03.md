# 2026-11-03 보드 실험과 결정

## 측정 범위

물리 Orange Pi 보드에서 사용자가 실행하고 공유한 터미널 결과를 기록했다. 이 저장소에 추가하는 과정에서 보드 측정을 다시 실행한 것은 아니다.

라이브 시간은 선택한 프레임의 전처리 시작부터 압축 완료까지이다. 첫 프레임을 제외한 중앙값·p95와 실행 전체 FPS를 사용한다. 최신 프레임 선택 방식으로 일부 촬영 프레임을 건너뛴다. CPU 코어 정책은 기존 performance였으며 최종 실행에 taskset은 사용하지 않는다.

## 네 가지 개선안

| 방안 | 결과 | 선택 |
| --- | --- | --- |
| CPU 큰 코어 고정·스레드 | 새 프로세스로 고정한 재측정에서 큰 코어 4스레드가 전체 코어 4스레드보다 빨라지지 않음 | 기존 코어 범위·4스레드 유지 |
| HM 옵션 | 고정 카메라 특징에서 1,029.1→623.7ms, payload 10,842→11,992B | combined4·QP20 |
| FENet NPU | 단독 540.8→113.9ms, 고정 입력 압축·복원 및 라이브 개선 확인 | NPU |
| 파이프라인 | FPS 증가와 함께 프레임 지연 증가 | 순차 실행 유지 |

처음의 프로세스 내 affinity 변경 결과는 기존 PyTorch 작업 스레드까지 모두 고정되었다고 보장하기 어려워 선택 근거에서 제외했다. 새 프로세스 측정에서 전체 코어 4스레드는 500.56/514.81ms, 큰 코어 4스레드는 524.41/521.40ms였다.

## HM 변경의 라이브 효과

| 항목 | 기존 전 | combined4 | 기존 후 |
| --- | --- | --- | --- |
| 프레임 처리 중앙값 | 1,680.1ms | 1,272.5ms | 1,696.3ms |
| FPS | 0.589 | 0.779 | 0.581 |
| HM 중앙값 | 1,032.8ms | 614.4ms | 1,045.8ms |
| 복원 검사 | 4/4 | 4/4 | 4/4 |

동일 고정 입력에서 HM 시간은 39.4% 줄었지만 payload는 10.6% 증가했다. 라이브 프레임 지연은 약 24~25% 감소했다. SAO 단독 효과는 거의 없었고 combined3·4의 작은 차이만으로 SAO의 추가 효과를 확정하지 않는다.

## FENet NPU의 라이브 효과

세 실행 모두 combined4를 사용했다.

| 항목 | CPU 전 | NPU | CPU 후 |
| --- | --- | --- | --- |
| Backbone 중앙값 | 94.3ms | 95.0ms | 94.5ms |
| FENet 중앙값 | 542.0ms | 113.4ms | 560.7ms |
| HM 중앙값 | 612.0ms | 612.7ms | 613.7ms |
| 프레임 처리 중앙값 | 1,263.8ms | 835.0ms | 1,279.9ms |
| p95 | 1,292.9ms | 889.2ms | 1,308.1ms |
| FPS | 0.784 | 1.153 | 0.773 |
| 복원 검사 | 4/4 | 4/4 | 4/4 |

프레임 지연 약 34~35% 감소, FPS 약 47~49% 증가를 확인했다. CPU와 NPU FENet은 완전히 동일하지 않으며, 10비트 정수화 값의 일부도 달라졌다. 세 입력의 압축·복원에서 원본 대비 전체 복원 오차는 비슷했으나 CPU/NPU 복원 특징 사이 상대 L2는 약 6.6~8.9%였다. 정확도 감소율이나 mAP로 해석하지 않는다.

## 파이프라인 제외 근거

한 개의 준비 작업 슬롯을 두고 다음 프레임의 Backbone/FENet과 이전 프레임의 HM을 겹쳤다. 대기시간도 프레임 지연에 포함했다.

| 항목 | 순차 전 | 파이프라인 | 순차 후 |
| --- | --- | --- | --- |
| FPS | 1.169 | 1.493 | 1.159 |
| 프레임 처리 중앙값 | 832.7ms | 1,295.4ms | 830.3ms |
| p95 | 880.3ms | 1,338.3ms | 888.6ms |
| HM 대기 중앙값 | 0ms | 401.4ms | 0ms |
| 복원 검사 | 4/4 | 4/4 | 4/4 |

FPS 약 28% 증가에 비해 프레임 지연은 약 56% 늘었다. 지연시간 감소라는 목표에 따라 적용하지 않는다. 파이프라인 종료 때 남은 작업 1개는 복원 실패가 아니다.

아래 도구는 보드 배치 후 기존 모델·표본이 있는 상태에서 실행한다. 비교 도구는 카메라를 점유하므로 동시에 실행하지 않는다.

대표 요약은 [board_summary.json](../results/2026-11-03/board_summary.json), FENet 단독·고정 입력 압축 비교는 같은 결과 폴더의 JSON에 있다. 라이브 전체 원시 CSV와 모델·촬영 데이터는 보드에 별도로 보관 중이다.
