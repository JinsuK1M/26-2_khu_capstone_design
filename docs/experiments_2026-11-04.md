# 서버 실험 기록 (2026-11-04)

모든 정확도는 Mac에서 측정했다. 측정 범위를 각 절에 적는다. 특징 오차(코사인, 상대 L2)와 단일 이미지 신뢰도는 mAP가 아니다.

## 2. 최종 분할 경로 정확도: COCO val2017 앞 500장

조건: 640 입력, YOLOX 공식 전처리(오른쪽·아래 114 패딩), dark3(l37) 분할, **FENet은 Mac CPU TorchScript**, HM combined4. uint8은 텐서별 min-max 단순 양자화 기준선.

| 방식 | 전송량/장 | mAP50 | mAP50-95 | 원본 대비 |
| --- | --- | --- | --- | --- |
| A. 원본 전체 모델 | – | 0.724 | 0.532 | – |
| C. 분할 + uint8 | 1,600KB | 0.724 | 0.533 | 동일 |
| D. 분할 + FCM QP20 | 19.89KB | 0.718 | 0.526 | −0.006 |
| D. 분할 + FCM QP25 | 11.70KB | 0.716 | 0.521 | −0.011 |

- 압축 전 dark3는 6,400KB(float32). QP20은 약 1/320.
- 앞 500장 부분 평가라 공식 5,000장 수치와 직접 비교하지 않는다.
- 평가 시간: A 285초, C 301초, D 약 475초 (HM 인코딩 포함).

## 3. HM 설정 비교: COCO128

FENet CPU. `default`는 학습 때의 `encoder_intra_main_rext.cfg`, `combined4`는 Edge 최종 설정.

| 방식 | 전송량/장 | mAP50 | mAP50-95 |
| --- | --- | --- | --- |
| 원본 | – | 0.825 | 0.605 |
| QP20 default | 19.70KB | 0.810 | 0.600 |
| QP20 combined4 | 20.64KB | 0.812 | 0.598 |
| QP25 default | 11.49KB | 0.809 | 0.593 |
| QP25 combined4 | 12.08KB | 0.802 | 0.596 |

combined4: 크기 약 5% 증가, mAP 차이 0.003 이내. COCO128은 학습 데이터와 겹칠 수 있어 경로 간 비교용이다.

## 4. 보드 NPU dark3 → 서버 (zidane 1장)

입력: 보드 `zidane_dark3_npu.npy` (전체 backbone RKNN의 dark3 출력). FCM 경로의 FENet은 Mac CPU.

| 경로 | person | person | tie | 개수 |
| --- | --- | --- | --- | --- |
| 원본 전체 모델 (Mac 전처리) | 0.940 | 0.887 | 0.790 | 3 |
| NPU dark3 → 서버 | 0.940 | 0.887 | 0.788 | 3 |
| NPU dark3 → FCM QP20 default (18.6KB) → 서버 | 0.941 | 0.885 | 0.765 | 3 |
| NPU dark3 → FCM QP20 combined4 (19.3KB) → 서버 | 0.942 | 0.885 | 0.761 | 3 |

박스 위치 차이 약 1~7픽셀. Mac 전처리 입력은 보드 입력과 픽셀 최대 1 차이(OpenCV 버전 추정).

## 5. 보드 최종 payload → 서버 (카메라 1프레임)

입력: 보드 `live_dark3_fcm.py` 최종 설정 실행의 `last_payload.bin` (processed 70, capture_id 878).

| 항목 | 결과 |
| --- | --- |
| 보드 설정 | NPU FENet, HM combined4, QP20, 보드 처리 828ms |
| payload | 13,397 bytes = 헤더 24 + HM 13,373, 길이 검사 통과 |
| 서버 복원 | 성공 |
| 서버 시간 (Mac) | 복원 173ms + 탐지 204ms |
| 원본 모델과 같은 물체 | 6개 중 5개 (신뢰도 0.05 이상, 같은 클래스·IoU 0.5 이상) |
| 보드 복원 dark3 vs Mac 압축·복원 dark3 | 코사인 0.997 |

천장·벽 위주 프레임이라 원본 모델도 신뢰도 0.25 이상 물체가 없다. 기능 확인이며 정확도 비교로는 부족하다. 두 실행 환경에서 보드 payload 경로의 탐지 결과는 완전히 같았다.

## 6. 서버–클라이언트 (Mac 단독)

| 항목 | 결과 |
| --- | --- |
| frame_id 반환 | 보낸 순서와 일치 |
| 잘못된 payload (잘린 파일) | 오류 응답, 연결 유지, 다음 프레임 정상 처리 |
| bus / zidane 탐지 개수 | 6 / 3, 원본 모델과 같음 |

같은 Mac 안 통신이라 네트워크 시간은 의미 없다. 보드 CPU 복원(약 1,014ms, Edge 기록)과 비교하면 Mac 서버 복원이 약 5배 이상 빠르다.
