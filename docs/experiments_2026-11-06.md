# 2026-11-06 HW FCM 통합·대역폭 결과

전날 밤부터 이어진 보드 측정을 포함한다. 값은 사용자가 제공한 실제 보드 터미널 요약에서 기록했으며, 로컬 Mac에서 재측정한 값이 아니다. 모델/촬영 이미지/특징은 포함하지 않는다.

## 동일 특징의 코덱 비교 (60장)

| 항목 | SW HM combined4 | HW 8bit NV12 all-I |
| --- | ---: | ---: |
| 코덱 시간 중앙값 | 653.1ms | 3.9ms |
| 보드 합산 중앙값 | 862.2ms | 214.3ms |
| 평균 비트스트림 (헤더 제외) | 19,304B | 18,336B |
| 원본 대비 특징 상대 L2 중앙값 | 0.2962 | 0.3008 |

동일 NPU FENet 출력을 두 경로에 사용. HW는 10→8변환/NV12패킹 포함, SW는 프로세스/I/O 포함. 보드 합산은 공통 연산과 코덱 시간의 합으로 서버 E2E가 아니다. 동일 QP20은 동일 품질이 아니다. HW vs SW 복원 특징 상대 L2 중앙값 0.1025는 mAP 하락률이 아니다.

서버 담당자 샘플 3장 비교: 원본 모델 탐지31개 중 SW/HW 일치 각26개, 추가 SW6/HW8개. 이는 정답 라벨 기반 평가가 아니며 mAP가 아니다.

같은 PNG60장, 같은 순서·SHA256. 저장 입력을 대기 없이 순차 처리하며 카메라 실시간 입력 시험이 아니다. PNG읽기/초기화/워밍업 제외, 보드 전처리/압축부터 탐지 응답 수신까지 포함. payload는 네트워크 오버헤드·응답 제외.

HW FCM은 다른 세 경로와 별도 시점에 측정했다. 서버 처리 중앙값도 이전 SW 약365~390ms vs HW 약294~308ms로 달라 전체 개선을 인코더 효과 하나로 귀속할 수 없다. 각 조건 1회 실행이며 정확도 동등 여부는 미확인이다.

HW FCM p95: 5Mbps 581.6ms, 3Mbps 612.2ms, 1Mbps 660.0ms, 0.5Mbps 662.9ms. 모두60장 완료, restored=true.

TBF는 서버 방향 TCP 업로드만 제한. burst16KiB/latency5초로 작은 FCM payload의 초기 burst가 허용될 수 있다. 상한 설정과 실측 가용 대역폭은 다르다. HW 후보 결과는 기존 SW를 대체 확정한 결과가 아니다.
